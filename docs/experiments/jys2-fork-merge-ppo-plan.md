**검증할 질문**은 두 가지다. 도로 단위의 경로 의도와 합류 차량의 도착시간 차이를 보여주면 기존 가감속·차로변경만으로 완주율과 충돌률이 개선되는가? 동일 조건에 기동 선택 단계를 추가하면 더 나아지는가? 이 문서는 실행 전 계획이다. 기준 소스는 `jys2@b1ca1b411afb790ec65fbe63a548b0fb52013ca2`다.

>
> 내 실험 저장소의 jys2에서 이 문서대로 구현하고 실행해 줘. 먼저 실제 HEAD, [AGENTS.md](../../AGENTS.md), 아래 기준 코드와 실행 환경을 확인해. 비교군과 평가 조건을 기록한 다음 사전검증, 짧은 PPO 업데이트, 본 학습, 독립 평가 순서로 진행해. 결과는 seed별 분자·분모와 실패 장면을 포함해 docs/experiments에 정리해. 실행 가능한 CLI와 재현 명령을 남기고, 미실행·중단된 조건은 구분해 줘.

## 2. 비교군과 고정 조건

| 조건 | 관측 | 준비 보상·위험 비용 | 정책 행동 |
| --- | --- | --- | --- |
| B1 기준 | 기존 38개 | 기존 B1 | 가감속 + 좌·유지·우 |
| O · 관측 효과 확인 | 아래 6개 추가 | B1 동일 | B1 동일 |
| A · 기존 행동 실험 | O 동일 | 아래 일회성 준비 보상 및 위험 비용 | B1 동일 |
| M · 전용 모드 실험 | A 동일 | A 동일 | 기동 선택 후 가감속 + 좌·유지·우 |

O−B1은 관측, A−O는 보상 변경 **묶음**, M−A는 모드 정책 구조의 효과를 비교한다. 준비 보상과 위험 비용 각각의 효과까지 주장하려면 A에서 한 항목씩만 켠 후속 비교가 필요하다.

- [실험 B](../../utils/experiment_b.py)의 `environment`, `agent_for`, `Episodes`와 PPO 설정을 재사용한다. 학습은 고교통 `high_real_ratio`, 16개 경로 순환, 출발 차로 0·1 교대, seed 11·22·33 각각 60만 스텝, 5만 스텝마다 저장한다. 도로·HV 구성, 센서 범위, 0.2초 스텝, 3,000스텝 제한은 공통이다.
- 각 조건은 **무작위 초기화한 순수 PPO**로 시작한다. 기존 가중치, BC·DAgger, 안전 게이트, 경로별 지정 차로 제어는 사용하지 않는다. B 실험처럼 `route_conn=False`를 확인한다. 지도 실선·차로 경계 등 기존 이동 제약은 유지한다.
- PPO는 기존 설정(학습률 0.0001, rollout 2048, epoch 10, minibatch 64, γ 0.99, λ 0.95)을 쓴다. 새 모듈은 별도 실험 이름, 별도 출력 경로를 사용한다. 각 실행에 실제 커밋·관측 필드 순서·보상 계수·seed·초기 가중치 해시·SUMO/패키지 버전을 기록한다.
- **에피소드 경계 확인**. [PPO.collect_rollout](../../algorithms/ppo.py)에서 시간 제한이면 이미 마지막 관측의 `γV`를 더한다. [compute_gae](../../utils/buffer.py)가 다음 에피소드까지 이어지지 않도록 이 방식에서는 버퍼의 경계 표시에 `terminated or truncated`를 쓴다. 실제 종료는 bootstrap 0, 시간 제한은 마지막 상태에서 한 번만 bootstrap한다. 두 에피소드를 잇는 작은 테스트로 확인하고 네 조건에 동일 적용한다. 이번 비교에서는 조기 정지 종료를 추가하지 않는다.

## 3. O와 A 구현 · 환경이 제공하는 정보와 보상

**관측**. [RoadEnv._get_obs / split / step](../../utils/experiment_a.py)과 [지도 로더](../../utils/mcw_train.py)를 확장한다. B1의 첫 38개 값과 순서를 보존한다. O/A/M은 44개로 통일하고 정상·내부 edge·종료 시 관측 shape, Gym 공간, 정책 생성과 평가의 `obs_dim`을 한 정의에서 가져온다.

1. **분기 의도 3개**. 400m 이내 다음 분기의 `src,dst = path[j:j+2]`와 지도 로더가 갱신한 `ic.RAMPS`로 원핫 `[본선 계속, 램프 진출, 기타]`를 만든다. 본선 분기에서 다음 edge가 램프면 진출, 본선이면 계속이다. 나머지는 기타로 둔다. 분기 유무는 기존 거리 필드로 구별할 수 있다. 목표 차로 번호·오프셋·정답 기동은 정책 입력에서 제외한다.
2. **합류 거리·상대차 검출·도착시간 차이 3개**. 지도 연결을 `(to_edge, to_lane)`별로 묶고 서로 다른 진입 도로가 같은 차로에 연결되는 경우를 찾는다. ego 접근 차로 및 주행 경로에서 가장 가까운 해당 합류점까지 차로를 따라 잰 거리(400m 이내)를 사용한다. 거리 입력은 `d/400`, 해당 지점이 없으면 −1이다. 다른 진입로에서 합류 차로로 연결되는 차로를 달리는 차량 중 기존 시야 안에서 검출된 차량만 사용한다. 현재 위치·속도로 예상한 도착시간 차이의 절댓값이 가장 작은 차량을 고른다. 거리와 속도 단위는 m와 m/s다.
3. 차이의 부호는 `ETA_상대 − ETA_ego`로 고정한다. ETA는 남은 주행거리 / max(속도, 1 m/s), 입력은 차이를 10초로 나누어 [−1, 1]로 제한한다. 양수면 ego가 먼저 도착할 것으로 예상한다. 미검출은 `검출=0, 차이=0`, 거의 동시에 도착은 `검출=1, 차이≈0`으로 구분한다. 미래 궤적이나 다른 차량의 숨은 경로는 읽지 않는다.
4. **지도 판정 예시**. `206426298#1_0`과 `544292616_1`은 모두 `844484877_1`로 연결되어 경쟁한다. 반면 `37927509`와 `170059989#1`에서 `206426298`로 진입할 때는 서로 다른 차로에 연결된다. 두 사례를 양성·음성 테스트로 쓴다. 이 정의가 다루는 범위는 같은 차로로 모이는 합류이며, 단순히 두 도로가 만나는 지점 전체로 결과를 확대하지 않는다.

**A의 준비 보상**. B1은 차로 오차가 한 단계 줄면 보상하지만, 처음부터 올바른 차로였던 차량이 이탈 후 처음 복귀할 때도 보상받을 여지가 있다. A에서는 B1의 `McwCredit` 지급을 **교체**한다. `RoadEnv.step()`에서 이미 역추적하는 `targets`를 보상 계산에만 사용한다. 에피소드마다 분기 인덱스 `j`별로 초기화하고, 같은 분기를 여러 edge에서 보더라도 중복 지급하지 않는다.

- 최초 유효 관측에서 `best_error[j] = min(abs(lane - t) for t in targets)`. 목표 차로 집합이 비었거나 모든 차로가 가능한 구간은 건너뛴다.
- 같은 외부 edge에서 실제 차로가 변경되고 전후에 같은 목표 집합을 적용할 수 있으면 `gain = max(0, best_error[j] - error_after)`로 계산해 `+0.3 × gain`을 한 번 지급하고 최저치를 갱신한다. edge 전환이나 목표 집합 변화로 오차가 작아지면 **무지급으로** 최저치만 갱신한다. 처음부터 정답이면 이탈·복귀 보상은 0이다. 충돌 종료 스텝에 준비 보상을 지급하지 않는다.
- 기존 [RoadEnv.step의 인접 차량 위험 계산](../../utils/experiment_a.py)을 재사용한다. 유효한 새 차로변경 시도당 기존 A3/A4 방식의 `−0.1 × risk`를 최대 한 번 적용한다. 좌우 겹침 또는 앞·뒤 차량이 빠르게 접근하는 경우에 비용이 생기며, 입력 명령을 취소하지 않는다. 기존 종방향 TTC 보상과 충돌 벌점 −15는 유지한다. 위험 비용·준비 보상·충돌 보상을 개별 로깅한다. A와 M에 동일 적용한다.

## 4. M 구현 · 기동 선택도 PPO가 학습

[HybridActorCritic](../../utils/networks.py)에 실험용 정책 타입을 추가한다. 매 스텝 ① 관측에서 `일반 / 본선 통과 준비 / 진출 준비 / 합류 조율` 중 한 기동을 샘플링하고, ② 공유 은닉층 출력과 선택한 기동의 임베딩을 결합해 연속 가감속과 좌·유지·우를 함께 결정한다. critic은 선택 전 관측으로 `V(s)`를 계산한다. 1차 실험에서는 기동 강제 유지 시간을 두지 않는다.

- 일반은 항상 가능하다. 분기 접근에서는 본선·진출 **둘 다**, 합류 접근에서는 합류를 추가 허용한다. 구간이 겹치면 합집합이다. 마스크는 A와 같은 관측의 분기·합류 거리 유무로만 만든다. 기동 이름이 실제로 다른 행동을 유도했는지는 결과에서 확인한다.
- 버퍼에는 `[accel, lane_cmd, mode_id]` 및 joint log probability를 저장한다. SUMO에는 처음 두 값만 보낸다. PPO 업데이트는 **저장된** mode로 `log π(mode|obs) + log π(accel|obs,mode) + log π(lane|obs,mode)`를 다시 계산한다. 기동을 다시 샘플링하거나 모드 선택에 정답 보상을 주지 않는다.
- `sample`, `evaluate_actions`, `det_action`, `collect_rollout`, `predict`와 평가 입력을 함께 확인한다. 결정론 평가에서는 기동 argmax 후 해당 기동의 평균 가속·최빈 차로를 쓴다. 기존 차로 엔트로피 계수는 유지하되 모드별 차로 엔트로피를 모드 확률로 가중 평균한다. 기존 2차원 정책의 학습·평가도 계속 가능해야 한다. 모드가 특정 차로를 자동 선택하거나 SUMO에 경로 변경을 요청하지 않게 한다.

## 5. 실행 순서와 합격 기준

**실행 진입점**. 담당 Codex는 위 기존 모듈을 재사용해 아래 CLI를 구현한다. 이는 새로 만들 명령의 계약이다. 각 단계의 실제 명령과 결과 위치를 최종 보고서 첫 부분에 기록한다.

```bash
python -m utils.fork_merge_ppo preflight
python -m utils.fork_merge_ppo smoke --arms B1 O A M --seed 11
python -m utils.fork_merge_ppo train --arms B1 O A M --seeds 11 22 33 --steps 600000
python -m utils.fork_merge_ppo evaluate --arms B1 O A M --seeds 11 22 33
python -m utils.fork_merge_ppo report
```

1. **사전검증**. 고정 위치·속도·교통으로 첫 표의 네 칸을 재현한다. 경로만 교환하면 분기 지시가 바뀌고 차량 센서가 같은지 확인한다. 합류는 양성·음성 지도 사례, 상대차 없음·동시·먼저·나중 도착을 시험한다. 준비 보상은 정답 출발→이탈→복귀 0점, 오차 1→0→1→0은 첫 개선에만 +0.3이어야 한다. 여유 있는 변경은 위험 비용 0이고, 위험 시도는 비용을 받아도 명령은 실행 경로에 전달돼야 한다.
2. **짧은 학습**. 조건별 최소 한 rollout과 PPO 업데이트를 끝낸다. 업데이트 직전 같은 관측·행동의 old/new log probability 비율이 1에 근접하고 결측값이 없는지, 체크포인트 저장·재로딩 전후 결정론 행동이 일치하는지 확인한다. M에서는 모드별 확률·선택·차로·가속을 기록한다. 실패하면 해당 검사를 수정 후 재실행한다.
3. **본 학습과 평가**. [기존 평가기](../../utils/experiment_b_eval.py)의 16개 경로와 두 출발 차로, 결정론 평가, 실제 초기 상태 일치 검사를 사용한다. 학습 seed와 별도로 선정용 교통 seed 810000/810001을 쓰고, 고교통 분기 쌍 성공→완주→적은 충돌→이른 체크포인트 순으로 선택한다. 최종 판정은 선정 모델과 고정 60만 모델 모두에서 본다. 독립 평가에는 이 실험의 학습·선정에 사용하지 않은 교통 base seed(예: 930000, 930100, 930200, 930300)에 출발 차로 0/1을 더해 쓴다. 모든 조건에 같은 조합을 적용한다. 고교통이 주 평가, 무교통·저교통은 실패 원인 진단용이다.
4. **결과표**. 조건·학습 seed별로 ① 13·16번 × 출발 차로 0·1 각각의 올바른 분기 통과/시작 횟수, ② 같은 초기 상태에서 두 경로 모두 통과한 쌍/전체 쌍, ③ 오차로 끝 정지 에피소드/시작 횟수, ④ 전체 완주·충돌·시간초과/전체 주행을 보고한다. 합류는 진입한 접근 건수를 분모로 쓰고, 접근 시작부터 합류 차로 진입 후 2초까지 ego 충돌이 발생한 접근을 분자로 센다. 동일 접근은 한 번만 세고 합류 도달률과 상대차 검출 건수도 병기한다. M은 모드별 선택 빈도와 같은 상태에서 선택 모드에 따른 가감속·차로 분포를 제시한다.
5. **판정**. 우선 A 대 B1, 그다음 M 대 A를 본다. 고교통에서 16번·0차로와 전체 완주율이 개선되고 13번·1차로 성공률 및 안전성(전체·합류 충돌률)이 악화되지 않는 방향인지 seed별로 확인한다. 작은 분모, 충돌 증가, seed 간 반대 결과, 한 모드로의 쏠림은 그대로 보고한다. 무교통에서만 성공하거나 시간초과가 충돌로 옮겨간 결과는 개선으로 채택하지 않는다.
6. **인계**. 실행 조건·재현 명령·체크포인트 선택 근거·seed별 결과 CSV·대표 실패 로그 요약·완료 여부를 `docs/experiments`에 남기고 색인에 연결한다. 대형 가중치와 원시 로그는 로컬에 보관한다. 실패 장면에는 경로, 진입 차로, 분기 거리, 선택 모드, 요청·실제 차로, 상대 도착시간, 종료 원인을 함께 기록한다.
