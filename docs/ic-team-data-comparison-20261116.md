# 팀별 관측 및 저장 데이터 비교

확인 기준일: 2026-11-16. 아래 내용은 당시 확인한 문서와 모델 기준이며, 이후 브랜치 변경 사항은 포함하지 않는다.

**“정책이 보는 관측”과 “실제로 저장한 데이터”를 나누면 차이가 명확하다.**

- **○** 있음 · **×** 해당 모델에서 사용하지 않음/해당 자료에 미저장
- **△** 일부만 있음 · **?** 수집 완료 여부를 문서에서 확인하지 못함
- 우리 쪽은 정리한 **상위 3개 모델** 기준이다.

² `mcw`는 별도 입력 칸을 추가하기보다 **기존 앞차·옆 차 관측에 합류 차량을 반영**하는 방식이다.

³ 합류 도달시간 겹침을 계산해 선택한 위험을 전방 장애물 형태로 입력한다. 시간차 등을 각각 직접 입력하는 `pmh`와는 다르다.

⁴ 확장 전방 위험 존재·거리·상대속도는 있지만, `ljj`의 네 지표 전체를 갖춘 것은 아니다.

**관측 차원이 크다고 정보가 더 많은 것은 아니다.** 우리 상위 모델은 63칸 중 **27칸이 0 고정**이고, 다른 팀원들은 빈 칸을 서로 다른 정보로 활용했다. 우리 최근 합류 실험은 상위 모델과 달리 60~62번을 사용했지만, 위 표에는 섞지 않았다.

## 3. 팀별 차이 요약

| 대상 | 특징적인 데이터 | 현재 확인된 저장 상태 |
|---|---|---|
| **우리** | 내비게이션 반응, 올바른 차로 유지, 위험 시 감속, 보상 누적량 | 평가·진단 로그 중심. 상위 모델의 전체 transition 자료는 없음 |
| **`gap-lane-22`** | 끼어들기 간격·목표 속도, 확장 전방 위험, 차로변경·재변경 횟수 | **1,600회 평가 CSV**. 최종 모델의 전체 스텝 수집은 환경 연결이 필요하다고 명시 |
| **`mcw`** | 경로에 맞는 차로 연결성, **400m 안내**, 연속 분기, 합류 사각지대 차량 | 필수 항목을 지원하는 수집기 문서가 있음. 최종 모델 수집량·완료 기록은 미확인 |
| **`pmh`** | 합류 경쟁 차량과의 시간·속도·거리 차이, 합류 후 공간, 필터 개입 | **80에피소드·38,773 transition 수집 완료**를 명시 |
| **`ljj`** | 안내 유효성, 앞차 존재·역TTC·필요감속도·겹침 | 수집 실행기와 **69 transition 점검 기록**. 최종 비교 결과는 주행별 요약 중심 |

**현재 문서상 전체 스텝 데이터 수집 완료가 가장 명확한 것은 `pmh`다.** 반면 우리와 `gap-lane-22`는 평가 결과가 있어도, 제출용 전체 transition 데이터는 별도로 수집해야 하는 상태다. `mcw`의 체크리스트 ○와 우리 표의 ×는 **구현 지원 여부와 실제 저장 여부라는 기준 차이**도 있으므로 그대로 우열로 보면 안 된다.
